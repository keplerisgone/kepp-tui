# KEPP TUI — Project Launcher v0.1 구현 명세

Specification v0.1 · 2026-10-27

목표: `kepp-tui` 안에서 로컬 프로젝트를 등록하고 검색한 뒤, 선택한 프로젝트의 작업 환경을 빠르게 여는 터미널 기반 Project Launcher를 구현합니다.

Project Launcher는 프로젝트 관리 시스템이 아닙니다. 프로젝트 경로와 설명, GitHub 저장소 식별자, 이후 버전에서 사용할 실행 명령을 등록하되 Git, Codex, KEPP LAB의 데이터를 복제하지 않습니다.

```text
kepp-tui
├── kepp project
├── kepp github
└── kepp calendar
```

Project Launcher의 진입점은 `kepp project`입니다. 별도 `pj` 명령은 지원하지 않습니다.

## 1. 버전별 범위

| 버전 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| v0.1 | 프로젝트 등록·등록 해제·검색·선택 | `kepp project`에서 프로젝트를 찾고 선택 가능 |
| v0.2 | Git 정보와 사용자 명령 관리·실행 | 프로젝트별 Git 상태 확인과 명령 실행 성공 |
| v0.3 | SSH 원격 프로젝트와 tmux 세션 | 원격 프로젝트 접근 및 작업 환경 복원 |
| v0.4 | Codex 연계 | 선택한 프로젝트에서 Codex 실행·재개 |

v0.1에는 실제 Git 명령 실행, Neovim·Codex 실행, 사용자 명령 실행, tmux 세션 생성, SSH 원격 프로젝트를 포함하지 않습니다.

## 2. v0.1 기능 요구사항

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| PJ-01 | 프로젝트 목록 | 등록된 프로젝트의 이름과 경로 표시 |
| PJ-02 | 프로젝트 상세 | 설명, 경로, 저장소 식별자와 경로 상태 표시 |
| PJ-03 | 프로젝트 등록 | 유효한 로컬 디렉터리를 registry에 추가 |
| PJ-04 | 프로젝트 등록 해제 | 확인 후 registry에서만 제거 |
| PJ-05 | 프로젝트 검색 | 이름·경로·설명에서 대소문자 비구분 검색 |
| PJ-06 | 프로젝트 선택 | 선택 상태와 상세 정보 갱신 |
| PJ-07 | 설정 유지 | 재실행 후 등록 정보 유지 |
| PJ-08 | 오류 처리 | 손상된 설정과 사라진 경로를 안전하게 표시 |
| PJ-09 | 키보드 조작 | 마우스 없이 등록·검색·선택·등록 해제 가능 |

프로젝트 등록 해제는 registry 항목만 제거합니다. Project Launcher는 실제 프로젝트 디렉터리나 그 안의 파일을 삭제하지 않습니다.

## 3. 화면 및 상호작용

```text
KEPP / Projects

PROJECTS
> kepp-lab       ~/workspace/kepp-lab
  mini-shell     ~/workspace/mini-shell
  network-lab    ~/workspace/network-lab
  logs           ~/logs

DETAIL
kepp-lab
AI-assisted development workspace

DIRECTORY
~/workspace/kepp-lab

REPOSITORY
keplerisgone/kepp-lab

STATUS
Directory available

Enter Select · / Search · a Add · d Unregister · r Refresh · q Back
```

화면은 다음 영역으로 나눕니다.

1. Project List: 등록된 프로젝트 이름과 축약 경로
2. Detail: 설명, 전체 경로, GitHub 저장소 식별자
3. Status: 경로 존재·접근 가능 여부와 오류
4. Status Bar: 키 바인딩과 현재 입력 상태

v0.1 화면에는 아직 실행할 수 없는 `Open Neovim`, `Launch Codex`, `Git status` 버튼을 표시하지 않습니다. 해당 동작은 v0.2 이후에 추가합니다.

## 4. 프로젝트 registry

registry는 버전이 있는 TOML 파일을 사용합니다.

```toml
version = 1

[[projects]]
name = "mini-shell"
path = "~/workspace/mini-shell"
description = "Unix shell implementation"
repository = "keplerisgone/mini-shell"

[projects.commands]
editor = ["nvim", "."]
agent = ["codex"]
test = ["make", "test"]
```

### 필드 규칙

| 필드 | 필수 | v0.1 처리 |
| --- | --- | --- |
| `version` | 예 | 지원하는 schema인지 확인 |
| `name` | 예 | 목록과 검색에 사용하는 표시 이름 |
| `path` | 예 | `~`를 확장하고 정규화하는 로컬 디렉터리 |
| `description` | 아니요 | 상세 화면과 검색에 사용 |
| `repository` | 아니요 | `OWNER/REPO` 표시용 메타데이터 |
| `commands` | 아니요 | 읽고 보존하지만 v0.1에서는 실행하지 않음 |

사용자 명령은 이후 안전한 프로세스 실행을 위해 셸 문자열이 아니라 실행 파일과 인자를 구분한 배열로 표현합니다. 파이프, 리다이렉션, 셸 확장이 필요한 명령 형식은 v0.1 범위에서 제외합니다.

### 경로와 중복 규칙

- 등록 시 `~`를 사용자 홈 디렉터리로 확장합니다.
- 내부 비교에는 정규화한 절대 경로를 사용합니다.
- 가능한 경우 canonical path를 기준으로 동일 디렉터리의 중복 등록을 차단합니다.
- Git 저장소가 아닌 일반 디렉터리도 등록할 수 있습니다.
- 등록 시 경로가 존재하고 디렉터리이며 접근 가능한지 확인합니다.
- 등록 이후 경로가 사라지면 항목을 자동 삭제하지 않고 경고 상태로 표시합니다.
- 같은 표시 이름은 허용할 수 있지만 동일 경로는 중복 등록할 수 없습니다.

### 저장 안전성

- registry 변경은 임시 파일에 쓴 뒤 원자적으로 교체합니다.
- TOML이 손상되면 빈 registry로 간주하거나 자동으로 덮어쓰지 않습니다.
- 저장 실패 시 기존 registry를 보존하고 오류를 표시합니다.
- 동시에 실행된 인스턴스의 변경을 조용히 덮어쓰지 않도록 잠금 또는 변경 재확인을 사용합니다.

registry의 정확한 플랫폼별 저장 위치와 TOML 라이브러리는 별도 ADR에서 확정합니다.

## 5. 프로젝트 등록과 등록 해제

### 등록

등록 폼은 최소한 이름과 경로를 입력받습니다. 설명과 저장소 식별자는 선택 사항입니다.

요청 전에 다음을 검증합니다.

- 이름이 비어 있지 않음
- 경로가 존재하는 디렉터리임
- 사용자가 해당 경로에 접근할 수 있음
- 동일 canonical path가 이미 등록되지 않음
- `repository`가 있다면 기본적인 `OWNER/REPO` 형식임

### 등록 해제

- `d`를 누르면 확인 화면을 표시합니다.
- 확인하기 전에는 registry를 변경하지 않습니다.
- 취소하면 선택과 목록을 유지합니다.
- 확인하면 registry 항목만 제거합니다.
- 로컬 디렉터리와 파일은 어떤 경우에도 삭제하지 않습니다.

UI와 문서에서는 `삭제` 대신 `등록 해제`라는 용어를 사용합니다.

## 6. 검색과 정렬

- 검색 대상은 프로젝트 이름, 경로, 설명입니다.
- 검색은 대소문자를 구분하지 않는 부분 문자열 검색입니다.
- 검색 입력 중에는 일반 단축키보다 텍스트 입력을 우선합니다.
- v0.1 기본 정렬은 프로젝트 이름 오름차순입니다.
- fuzzy ranking, 최근 사용 순서, 자동 디렉터리 스캔은 후속 버전으로 미룹니다.

## 7. 키보드 명세

| 키 | 동작 |
| --- | --- |
| `j` / `k` | 이전·다음 프로젝트 선택 |
| `/` | 검색 입력 |
| `Enter` | 현재 프로젝트 선택 및 상세 확인 |
| `a` | 프로젝트 등록 폼 열기 |
| `d` | 선택 프로젝트 등록 해제 확인 |
| `r` | 등록 경로 상태 다시 확인 |
| `Esc` | 검색·폼·확인 화면 닫기 |
| `q` | Project Launcher 종료 후 KEPP 메인 메뉴로 복귀 |

v0.1에서 Enter는 외부 셸의 현재 디렉터리를 변경하거나 tmux 세션을 만들지 않습니다. 선택한 프로젝트의 상세 정보를 확인하는 동작으로 제한합니다. 실제 작업 환경 실행 방식은 v0.2 이후 별도 명세에서 확정합니다.

## 8. 오류 처리

| 상황 | 기대 동작 |
| --- | --- |
| registry 없음 | 빈 목록으로 시작하고 첫 등록 안내 |
| TOML 손상 | 기존 파일 보존, 파싱 오류 표시 |
| 지원하지 않는 schema | 자동 변환하지 않고 지원 버전 안내 |
| 경로 없음 | 항목 유지, missing 상태 표시, 관련 동작 차단 |
| 디렉터리 접근 불가 | 권한 오류 표시 |
| 동일 경로 중복 | 등록 차단, 기존 프로젝트 안내 |
| 저장 실패 | 기존 registry 유지, 오류 표시 |
| 동시 변경 충돌 | 조용히 덮어쓰지 않고 새로고침 또는 재시도 안내 |
| 긴 경로·한글 | 안전하게 표시하고 필요한 경우 잘림 표시 |

오류가 발생해도 GitHub Console과 Calendar 등 다른 KEPP 모듈은 정상적으로 사용할 수 있어야 합니다.

## 11. 최종 Definition of Done

다음 사용자 시나리오가 모두 성공하면 Project Launcher v0.1이 완료된 것으로 판단합니다.

1. `kepp project`를 실행하면 등록된 프로젝트 목록이 나타납니다.
2. 로컬 디렉터리를 프로젝트로 등록하고 재실행 후에도 확인할 수 있습니다.
3. 이름·경로·설명으로 프로젝트를 검색할 수 있습니다.
4. 프로젝트를 선택하면 설명, 경로, 저장소 식별자와 경로 상태가 표시됩니다.
5. 프로젝트 등록을 해제해도 실제 디렉터리와 파일은 유지됩니다.
6. 사라진 경로와 손상된 registry가 기존 데이터를 조용히 삭제하지 않습니다.
7. 키보드만으로 모든 v0.1 동작을 수행할 수 있습니다.
8. macOS, Linux 및 tmux에서 기본 흐름을 완료할 수 있습니다.

## 12. 후속 버전

v0.2에서는 실제 Git branch/status 조회, 프로젝트 명령 추가·수정·실행, Neovim 실행을 구현합니다.

v0.3에서는 SSH 원격 프로젝트와 프로젝트별 tmux 세션 생성·재연결을 구현합니다.

v0.4에서는 선택한 프로젝트에서 Codex를 실행하고 기존 작업을 재개하는 기능을 구현합니다. KEPP LAB의 승인과 자동화 정책은 Launcher에 복제하지 않고 기존 Worker가 계속 담당합니다.

## 13. 유지할 설계 원칙

- Project Launcher는 프로젝트를 빠르게 찾고 작업을 시작하는 도구입니다.
- Git은 코드 이력, Codex는 개발 수행, KEPP LAB은 자동화를 담당합니다.
- Launcher는 외부 도구의 상태를 별도 데이터베이스에 복제하지 않습니다.
- Project, GitHub, Calendar 모듈은 서로 실패 격리를 유지합니다.
- 공통 프레임워크나 플러그인 시스템을 미리 만들지 않습니다.
- 확정되지 않은 후속 기능을 v0.1에서 임의로 구현하지 않습니다.
